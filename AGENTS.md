## Every push is tested before it goes live

`.github/workflows/pages.yml` runs `tests/smoke_test.py` on every push to `main`, and only deploys to GitHub Pages if it passes. For every profession, the test starts a fresh game, makes a character, plays a few seconds and opens each panel (pack, skills, journal, weave book, craft, help, map). It then gathers a world node and crafts Field Stims through the Tradeskills panel (Build Q), opens the 🎲 mission board with N, accepts and delivers a supply run and claims it at the terminal (Build R), picks Hard on the Hollowvein Mine door's ⚔ Difficulty picker, enters and checks the scaled run, timer and tracker (Build S), goes home, buys a rug and places it in a slot through the 🏠 Home panel and checks rested XP shows on the XP bar (Build T), opens 🏅 Achievements with O, earns «Thousand Cuts» and checks its popup, then opens the Collection boss grid and the Wardrobe tab (Build U), climbs the 🗼 Vigil Stair one floor (key U, Build V) and picks a boon, switches Weave loadouts from the HUD, flips the action bar to page 2 and filters the Weave Book (Build W1), and checks that a save survives a reload. Finally a **phone pass** at short landscape sizes (750x342 and iPhone SE 667x375, touch) creates a character by tapping, shows a region banner and a tip, and fails if HUD elements overlap: tracker, minimap, banner or tip against the action buttons; banner against tip; tip/banner against the tracker, top buttons or frames. **Any page error or console error fails it.**

- After you push, check that the Actions run is green. If it's red, the live game is still on the previous build. Fix it and push again.
- Run it locally before pushing: `pip install playwright && python -m playwright install chromium && python tests/smoke_test.py`.

## The source lives in `src/`. Build from it, never edit the built files

The six files at the repo root (`index.html`, `three.min.js`, `sw.js`, `manifest.webmanifest`, `icon-180.png`, `icon-512.png`) are **build output**. GitHub Pages serves them, but they are generated from `src/`, and the next build overwrites any hand edit. Make every change in `src/` and rebuild.

- `src/game1.js` … `src/game42.js`: the game code (`game36.js` = Build Q gathering nodes + tradeskill ranks/recipes; character data in `P.craft`, saved through `craftFields()` in `futureFields`. `game37.js` = Build R random missions on the side-quest engine of `game16.js`; each mission keeps its generated definition in `q.rdef` and is re-registered by `rmReg()` on load; board/writs/daily/weekly state in `P.rmis`, saved through `rmFields()`; character sheets are `v:3`. `game38.js` = Build S hard modes: per-character difficulty per key `d:<id>` (solo door), `t:<id>` (team version) and `r:<id>` (raid), with tiers Normal/Hard/Nightmare plus Ascent I–V for solo doors (`HM_TIERS`), and Normal/Hard/Nightmare for team versions (`HM_TEAM`, which get half the tier's extra damage) and raids (`HM_RAID`, where the Sun-Eater's Total Eclipse is scaled by `hmEnrageK()`). `enterDungeon` calls `hmMode()`, which returns a scaled **copy** of the mode object with `mode.hm`; story runs are never scaled. Weekly twists come from `hmAffixes(tier, week)`, with the week being `P.gday/SUN_GWEEK`. Hooks in game5: `hmMob` in `spawnDunMob`, `hmOnKill`/`hmBonus`/`hmItem`/`hmClear` in `dunOnKill`, `hmTick` in `updDungeon`, and `hmPickHtml` in `openDoor` (also in game29 `teamDoorHtml` and the raid Team tabs in game14/game34). State lives in `P.hm` (v1), saved through `hmFields()`. For balance sims, `__dr.hmForce(tier, affixes)` forces a tier on the next entry; `hmForce(null)` clears it). `game39.js` = Build T apartment upgrades on top of the game8 apartment. Shared state (tier, furniture slots, owned pieces) lives in localStorage `dustreach_apt_v1` through `aptLoad()`/`aptWrite()`. Fixed `SLOTS` (floor/wall, unlocked by `APT_TIERS`) and the `FURN` catalogue (bought with credits or writs, crafted through `QREC` recipes `h_*` with `out:{furn}`, or dropped via `aptBossDrop` in `dunOnKill`). The trophy wall is built from the character's records (`trophies()`). Rested XP and trophy pins live in `P.home` (v1), saved through `homeFields()`; `restTick` accrues the pool and `restUse` doubles kill XP in game3. The 🏠 Home panel is `openHome(tab)` with actions in `homeAct`). `build.js` joins these into one `<script>` **in a fixed order** (see `ORDER` in `build.js`; later files patch earlier ones and `game4.js` boots the game last). If you add a file, add it to `ORDER`.
- `src/game43.js`: **cloud backup** (2026-11-23, Claude). Uploads the normal Export save (`exportData()`) to Dan's server `https://tools.nevarios.com/drsave/api` (private repo `6herk1n/dr-save`) with a per-device code made on the login-protected link page `https://tools.nevarios.com/drsave/`. The code lives in `dustreach_cloud_v1`, which is device-only and must **never** be added to `EXP_KEYS` (it would put the code in export files). Auto backup every 5 min while visible and on hide, only if the data changed, never with zero characters. ☁ Cloud tab in Save tools (wraps `openSaveTools`) lists backups; Restore = `parseImport`/`applyImport`. Nothing is sent until a device is linked, so tests make no network calls; `window.__DR_CLOUD_API` overrides the server for testing.
- `src/template.html`: the page shell and all CSS. Placeholders: `__BUILD__`, `__ICON__`, `<script>__THREE__</script>`, `__GAME__`.
- `src/sw.js`: the service worker template (`__BUILD__`, `__THREE_URL__`).
- `src/icon.b64` (becomes `icon-180.png`) and `src/icon-512.png`.
- `src/vendor/three.min.js` + `THREE_VERSION`: Three.js r150 (0.150.1), vendored so the build needs no `npm install`.

### How to build

```
node build.js            # writes the 6 root files in place (Node 18+, no dependencies. `game40.js` = Build U achievements and collections: `ACH` (id, category, points, a progress reader `v()` and goal `g`, optional reward `rw` = title/writs/companion/vehicle/furniture) is checked from the character's records every ~2 s of wall-clock time by `achTick()` (called from `updHUD` via `achFrame`), so old characters are credited on first load (silent backfill, `P.ach.bf`). Event-only feats live in `P.ach.ev` (no-death clears from `DUN.pd` set in `playerDie`, hooked in game5 `achClear`; dyna kills from game17 `achDyna`; rare kills). Collection state `P.coll` (uniques seen in pack/gear/implants/bank or learned disks, unlocked looks `slot|fam-or-wt|rarity`, transmog `xm`, companions). Both are v1 and saved through `achFields()` in `futureFields`. Transmog: game25 `refreshGearVisual` draws `xmogEq(P.eq)` (looks only change `fam`/`wt`/`r`, never stats). Cosmetic companions `COMPS` are code-built followers; new achievement vehicles are added to `VEHICLES` and achievement furniture to `FURN`/`FURN_B`. Rare spawns `RARES` (one near each dyna, `rrTick`, minimap ✦ via `rrMini`) never spawn in sims (`SIMP`/`SIMST`) or dungeons; `__dr.RR.off=true` turns them off). `game41.js` = Build V Vigil Stair endless tower: a tower outside Halden's Rest (`VG_POS`, door `vgWorldInteract`) or the ⋯ menu/key U opens `openVg(tab)`; a run is an apartment-like `DUN` with `DUN.vg` (run state, exposed as `__dr.vgRun`) in a rebuilt 32×32 arena (`vgBuild`). Floors: `vgBegin`/`vgWave`/`vgClear`, guardian every 5th (`VG_GUARD`, `vgGuardTick`), landing/checkpoint every 10th, mobs scaled by `vgHpK`/`vgDmgK` past the level cap, hard-mode weekly affixes from floor 11 (`vgAffixes`). Pick-one-of-three boons `VG_BOONS` between floors (`vgRoll`/`vgApply`), hooked into game3 damage (`vgOut`/`vgIn`/`vgThorns`/`vgSave`) and death (`vgDie`, no fee or XP loss). Records/marks/shop in `P.vg` (v1, `vgFields()` in `futureFields`), weekly best via `gweekKey()`; Keeper's shop `VG_SHOP`, achievements category `vg`. `vgSimClimb` drives the sim bot. `game42.js` = Build W1 Weave framework: families `wvFam(w)` (`WV_FAMS`: nuke/aoe/dot/debuff/self/team/heal/cc/util/pet, `w.fam` overrides); **cast requirements**: a Weave's `req` must be met to cast it (`wvReqMiss`, checked in a `useAbility` wrapper; 🔒 class `wlock` on HUD buttons), Weaves known before W1 are grandfathered in `P.wv.gf`; **Matrix**: buff Weaves (`w.buff` or kind `teambuff`) occupy `wvMx(w)` (`w.mx` overrides) of `S.mxCap` (`mxCapFor`: level, implants, headgear, `mx` bonus; `statsFor` is wrapped), over cap refuses and opens `openMatrix()` to drop one, then casts the pending Weave; a higher rank of a running buff line replaces the lower (`wvSupersede`); **bar page 2** = `P.wv.s2` (book slot indices 6-11, `wvSlotGet/Set`), `P.wv.pg` picks the page `barIds()` returns (`#bPg` chip, swipe, Backquote); **loadouts** `P.wv.lo` [{n,ic,s1,s2,auto}] max 8, `P.wv.cur`, switched by `wvLoSwitch(i)` (HUD `#bLo` → `#loPop`, key V, book), `auto` presets fill from `wvAutoBar` until saved over; **team casting** `wvTeamCast(id)` puts a damage/DR boost (`tbSet`) on nearby AI teammates. The Weave Book (`openBook`, actions in `wvAct`) is replaced here: family chips, ★ best usable rank, 📍 `wvWhere(w)` (`w.src` overrides). Saved as `P.wv` v1 via `wvFields()` in `futureFields`. Sim characters (`simChar`) top up skills to meet every bar Weave's requirements and are not grandfathered.)
node build.js /tmp/out   # or into another folder, e.g. to compare builds
```

Each build gets a stamp `<UTC yyyymmddThhmmss>-<sha1 of the game code, 8 hex>`. It goes into `index.html` (`<meta name="dr-build">`, `window.DR_BUILD`) and into the `sw.js` cache name. That way every build installs a fresh offline cache and the in-game "New version" prompt fires. Commit the rebuilt root files together with the `src/` change that produced them.

### Tests

- `tests/check_build.js` (Node, no dependencies): also a deploy gate, run first by `pages.yml`. Rebuilds `src/` into a temp folder and fails if the committed root files differ (only the time part of the build stamp is ignored). If it fails, you edited a built file or forgot to rebuild: fix `src/`, run `node build.js`, commit both.
- `tests/check_save_keys.js` (Node, no dependencies): also a deploy gate. Every `'dustreach_*'` localStorage key in `src/` must be in `EXP_KEYS` (`src/game20.js`) so Export/Import carry it, or in the test's `DEVICE_ONLY` list with a reason (settings, backups, reminders). **If you add a new saved key, add it to `EXP_KEYS` and `EXP_OPT`** (`EXP_OPT` = keys an older save file may not have; import leaves those alone instead of wiping them). Keys must be fixed literals or `*_KEY` constants, never built at run time.
- `tests/smoke_test.py` (Python Playwright): the deploy gate run by `pages.yml`. Run it before every push (see above).
- `tests/smoke.js` (Node Playwright, `npm install` first): the builder's quick pre-publish check (iPad-sized touch viewport, save/reload).
- `tests/ci_smoke.mjs` (Node Playwright): info only, not run by CI. `SMOKE_ONLY=desktop|ipad|phone` runs one pass (phone = 750x342 with the HUD-overlap check; the same check now gates deploys via `smoke_test.py`).
- The builder's long regression suite (`test*.js`, about 40 Playwright scripts) is not in the repo yet: it is hard-wired to the builder's workspace layout.

Never commit `publish.sh`/uploader scripts, keys, tokens or e-mail credentials. Don't commit backups, screenshots, sim output or logs either.

## Screen layouts (src/template.html)

- Desktop and iPad (both orientations) use the base CSS. Keep them pixel-identical unless a change is meant for them.
- `@media (max-height:480px)`: phones in landscape. HUD scaled to about 70%. The Story tracker (`#mtrack`) sits under the top buttons. The region banner (122px) and tip toast (176px) are stacked in a centre column that clears the left frames and the right-hand tracker. The title and New Contractor screens scroll from the top.
- `@media (orientation:portrait) and (max-width:540px)`: phones held upright. Compact HUD, top buttons in a row under the player frame, tracker under the minimap, banner and tip mid-screen.
